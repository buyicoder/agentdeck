# Audit Evidence

This file records repeatable evidence for the required user full-journey
frontend audit.

## Validation Mode Evidence

Use the native panel before every alpha build:

1. Launch AgentDeck with `swift run`.
2. Run `Validation mode` with `Move windows` off.
3. Copy the validation report.
4. Grant Accessibility if needed, enable `Move windows`, and run `Validation
   mode` again.
5. Copy the second validation report.
6. Attach both reports to the audit record.

Required evidence fields:

| Field | Required | Notes |
| --- | --- | --- |
| Date/time | Yes | Generated by validation report. |
| Mode | Yes | `panel-only` or `real window actions`. |
| Scan summary | Yes | Confirms window enumeration ran. |
| Focus summary | Yes | Confirms active-side input source. |
| Step status | Yes | open, scan, detect, queue, promote, restore. |
| Undo frame count | Yes | Must increase after real promotion and decrease after restore. |
| Screenshot | Yes | Capture panel after each run. |
| Notes | Yes | Any confusing UI, missing explanation, or manual workaround. |

## Full-Journey Evidence Matrix

Validation mode is necessary but not sufficient. Alpha sign-off also needs
manual evidence for the parts that cannot be proven by the safe test window.

| Area | Evidence | Status |
| --- | --- | --- |
| First launch | Screenshot of initial panel state and next obvious action. | Required |
| Permission denied | Screenshot and notes after Accessibility is denied or unavailable. | Required |
| Permission recovery | Screenshot and notes after permission is granted and scan succeeds. | Required |
| Single-display scheduling | Left active -> right target, right active -> left target. | Required |
| External display scheduling | Window shown on secondary display with predictable primary-display target. | Required |
| Display unplug/replug | Stale or changed display labels are understandable and do not duplicate rows. | Required |
| Real agent detection | Codex, Cursor, WorkBuddy, browser, and terminal rows show app/window/conversation separation. | Required |
| Conversation switch | Old key, new key, and prior row state after switching within the same app window. | Required |
| Failure states | Low confidence, no windows, missing queued window, and move failure are visible in UI. | Required |
| Layout stability | Screenshots at narrow, default, and wide panel sizes. | Required |
| Keyboard path | Keyboard-only scan, queue, promote, run, done, restore path notes. | Required |
| VoiceOver readout | Notes for row identity: app, window, conversation, status, action. | Required |

## 2026-07-01 Promote Button Feedback Audit

## 2026-07-01 Flow Occupancy Model Correction

- Build: `swift build` passes.
- Install: `scripts/install_local_app.sh` reinstalled `/Applications/AgentDeck.app`.
- Screenshot: `/tmp/agentdeck-audit/flow-model-fix-display-3.png`.
- Root cause: the scheduler treated previously displayed left/right slot rows
  as persistent occupancy, but the product model only treats the user's current
  editing side as occupied.
- Result: queued agents now promote to the opposite side of the current editing
  side even when a previous review row is still visible in that slot.
- Result: `AgentDeck` itself is excluded from tracked app scans.
- Result: settings storage moved to `agentdeck.settings.v2`, defaulting to
  selected agent apps instead of all visible apps; browsers are listed but
  disabled by default.

## 2026-07-01 Realtime Workbench State Evidence

- Build: `swift build` passes.
- Install: `scripts/install_local_app.sh` reinstalled `/Applications/AgentDeck.app`.
- Screenshot: `/tmp/agentdeck-audit/workbench-state-final-display-3.png`.
- Result: AgentDeck now maintains a separate `WorkbenchState` for realtime
  editing-side facts instead of treating historical `ConversationSurface.side`
  as screen occupancy.
- Result: slot UI shows only the realtime focused agent side; when AgentDeck
  itself is frontmost, the panel does not count itself as an occupied side.
- Result: non-half-screen windows do not create left/right occupancy; focused
  windows must substantially cover a primary-screen half before they count as
  left or right editing.
- Result: the app refreshes snapshots every second as a lightweight bridge
  until AXObserver-based event updates are implemented.
